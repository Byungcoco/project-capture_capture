# 태스크 브리프 / 보고서 템플릿

조정자가 태스크마다 브리프 파일을 `.dispatch/<계획 basename>/task-<N>-brief.md`로 쓴다.
구현자는 보고서를 `.dispatch/<계획 basename>/task-<N>-report.md`로 쓴다.

`REQUIRED` 슬롯은 비울 수 없다. 비면 디스패치 불가 또는 보고 반려다.

---

## 브리프 템플릿 (조정자가 작성)

```markdown
# Task <N>: <한 줄 제목>

## 목표
이 태스크가 끝나면 무엇이 참이 되는가. 한두 문장.

## RED 명세  <!-- REQUIRED -->
구현 전에 작성해서 실패시킬 테스트.

- 테스트 파일: <경로>
- 테스트 이름: <동작을 서술하는 이름>
- 단언: <무엇이 무엇과 같아야 하는가 — 정확한 값으로>
- 기대하는 실패: <기능이 없어서 나는 실패여야 한다. 오타나 import 에러가 아니다>

비코드 산출물이면 이 슬롯에 `N/A: <문서 | 위키 | 에셋 | 설정값>`이라고 쓰고
아래 `## 검증`에 실행 가능한 확인 명령을 넣는다.

## 검증  <!-- REQUIRED -->
실행할 명령을 그대로 적는다.

```bash
pnpm test <경로>
pnpm typecheck
```

## 범위
건드릴 파일:
- <경로>

건드리지 말 것:
- <경로 또는 영역>

## 정확한 값
숫자, 문자열 리터럴, 함수 시그니처, 스키마 필드명, 테스트 케이스.
구현자는 여기 적힌 값을 그대로 쓴다. 지어내지 않는다.

조정자가 소스를 확인하지 못한 항목은 추정치를 넣지 말고
`미확인: <구현자가 소스에서 확정할 것>`으로 표시한다.
그럴듯한 추정치는 구현자가 사실로 믿기 때문에 빈칸보다 나쁘다.

## 전역 제약
계획의 Global Constraints 중 이 태스크를 구속하는 것만 그대로 옮긴다.

## 보고
보고서 파일: `.dispatch/<basename>/task-<N>-report.md`
전체 내용은 그 파일에 쓰고, 돌려주는 값은 status / 커밋 SHA / 테스트 한 줄 요약 / 우려사항뿐이다.
```

---

## 보고서 템플릿 (구현자가 작성)

```markdown
# Task <N> 보고서

## Status  <!-- REQUIRED -->
DONE | DONE_WITH_CONCERNS | NEEDS_CONTEXT | BLOCKED

## RED 증거  <!-- REQUIRED -->
테스트를 먼저 작성하고 구현 전에 실행한 결과의 **출력 원문**.

```
$ pnpm test src/foo.test.ts
FAIL  src/foo.test.ts > rejects empty email
  expected 'Email required', got undefined
```

실패 사유: <기능 미구현 때문임을 한 줄로>

서술만 적고 출력이 없으면 이 보고서는 반려된다.
비코드 산출물이면 `N/A: <종류>`와 함께 `## 검증 증거`를 채운다.

## GREEN 증거  <!-- REQUIRED -->
구현 후 통과 출력 원문. 다른 테스트도 함께 통과함을 보인다.

```
$ pnpm test
Test Files  12 passed (12)
     Tests  47 passed (47)
```

## 검증 증거  <!-- REQUIRED -->
브리프 `## 검증`의 명령을 전부 실행한 출력. 타입 검사와 빌드 포함.

## 커밋  <!-- REQUIRED: 테스트 커밋과 구현 커밋을 분리한다 -->
- <SHA> test: <실패하는 테스트만. 이 시점에 구현이 없어야 한다>
- <SHA> feat|fix: <구현>

## 변경 파일
- <경로> — <무엇을 왜>

## 보안 검토  <!-- REQUIRED -->
AGENTS.md `보안 검토 기준`의 적용 대상에 닿는가.

- 닿지 않으면: `해당 없음 — <이유>`
- 닿으면: 확인한 항목, 추가한 **거부 케이스 테스트**(테스트 이름), 미해결 위험
- `/security-review` 또는 `gstack:review`를 돌렸으면 결과, 안 돌렸으면 그 사실

방어를 설명하는 문장은 증거가 아니다. 완화하지 못한 취약점이 있으면
Status를 `DONE`이 아니라 `BLOCKED`로 적는다.

## 계약 변경
공개 인터페이스, 스키마, 이벤트, 에러 코드가 바뀌었다면 여기에. 없으면 `없음`.

## 우려사항
브리프대로 했지만 미심쩍은 것. 없으면 `없음`.
직접 결정하지 말고 여기에 올린다.
```

## 조정자 체크리스트

디스패치 전:
- [ ] `## RED 명세`가 채워졌다 (또는 `N/A: <종류>` + `## 검증`)
- [ ] `## 정확한 값`에 구현자가 지어낼 여지가 없다
- [ ] BASE SHA를 기록했다
- [ ] 모델을 명시했다
- [ ] 세션 히스토리를 붙여넣지 않았다

보고 수령 후:
- [ ] `## RED 증거`가 출력 원문이다
- [ ] `## GREEN 증거`가 출력 원문이다
- [ ] 실패 사유가 "기능 미구현"이다 (오타·import 에러가 아니다)
- [ ] 테스트 커밋이 구현 커밋보다 앞에 있다 — `git show <테스트 SHA>:<구현파일>`로 확인
- [ ] `## 보안 검토`가 채워졌다. 신뢰 경계를 지나면 거부 케이스 테스트가 있다
- [ ] 완화하지 못한 취약점을 `DONE`으로 통과시키지 않았다
- [ ] 리뷰 디스패치 (명세 준수 + 코드 품질 두 판정)
- [ ] 원장에 `Task <N>: complete — <SHA>` 추가
