# 🚨 [CRITICAL] 위키 직접 업데이트 강제 규칙

이 프로젝트에서 작업하는 **모든 LLM 에이전트(Claude, Gemini, Copilot 등)**는 이 규칙을 최우선으로 따릅니다.

## 1. 지식의 원본은 마크다운 파일 그 자체입니다
`tools/wiki_sync.py` 스크립트를 실행하는 것은 단지 검색 메타데이터와 **로그(log)**를 동기화하는 절차일 뿐입니다.
스크립트 실행만으로는 실제 **아키텍처, 렌더링 룰, 도메인 로직 등의 지식 내용이 위키에 기록되지 않습니다.**

## 2. 작업 후 문서 갱신 필수 절차
기능 개발, 버그 픽스, 아키텍처 변경 등의 작업을 완료하기 직전에 다음 절차를 **반드시** 거쳐야 합니다.
1. **직접 작성/수정**: 이번 작업으로 인해 새롭게 확립되거나 변경된 지식(WebGPU 설정, Game Loop 등)을 `docs/wiki/06-code/` 하위의 적절한 마크다운 원본 파일(예: `platform/web-rendering.md`)에 **직접 파일 쓰기 도구(write_to_file 등)**를 사용해 기록하세요. 문서가 없다면 새로 만드세요.
2. **스크립트 실행**: 문서 갱신을 마친 후 `python tools/wiki_sync.py finalize ...`를 실행하여 시스템 로그에 반영하세요.

## 3. 누락 금지
- 어떠한 상황에서도 "다음 작업에 업데이트 권장", "스크립트만 돌리고 끝"으로 마무리해서는 안 됩니다.
- 코드 변경점이 지식 보존 가치가 있다고 판단되면, 스크립트 실행 전에 원본 `.md` 파일을 수정하는 것이 완료 조건에 강제로 포함됩니다.
