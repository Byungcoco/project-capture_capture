# develop-jaehyeok 피벗 구현 계획

## 계획 지위

이 계획은 [[../../04-decisions/proposals/develop-jaehyeok-pivot|피벗 제품 제안]]과 [[../../03-tech/proposals/develop-jaehyeok-implementation-design|피벗 구현 설계]]를 실행하는 `develop-jaehyeok` 브랜치 전용 원장이다. 본류 [[../current|Current]]의 마일스톤을 변경하지 않는다.

각 마일스톤은 하나의 플레이 가능한 결과를 만들고, 다음 단계로 넘어가기 전에 RED 출력, GREEN 출력, 전체 테스트, 타입 검사·빌드와 지정된 브라우저 확인을 남긴다. 구현 도중 새로운 제품·기술 판단이 필요하면 이 문서를 조용히 바꾸지 않고 피벗 제안 또는 별도 draft ADR에 기록한다.

## 성공 정의

첫 피벗 데모는 다음 장면을 한 세션에서 설명 없이 수행할 수 있을 때 완료다.

```text
3인칭으로 공중 섬 이동
→ 지형 절취 캡처
→ 스택 확인
→ 공중 배치
→ 배치 지형으로 와이어 이동
→ 대시·더블 점프 연계
→ 보스 공격 캡처·재사용
→ 파괴되는 전장에서 보스 처치
```

## 작업 원칙

- `src/pivot`에 새 구현을 격리하고 기존 본류 모듈과 테스트를 보존한다.
- 각 동작은 실패 테스트를 먼저 작성하고 기능 부재로 실패한 출력을 확인한다.
- 자동 단언이 어려운 조작감은 각 마일스톤의 브라우저 플레이테스트 절차로 검증한다.
- 새 의존성은 사용하지 않는다. 필요해지면 ADR과 보안 검토 후 별도 변경으로 추가한다.
- 맵 미술과 보스 콘텐츠보다 이동·캡처·배치의 핵심 재미를 먼저 검증한다.
- 마일스톤 하나가 실패하면 다음 기능을 쌓지 않고 원인과 판정 결과를 기록한다.

## 마일스톤 0 — 피벗 런타임 골격

### 결과

기존 데모를 보존한 채 `src/pivot`의 순수 3D session과 Three.js adapter가 고정 틱으로 빈 테스트 월드를 실행한다.

### RED

- `stepPivotSession`이 같은 초기 상태와 같은 명령에서 같은 snapshot을 생성한다는 테스트를 먼저 추가한다.
- 존재하지 않는 피벗 session import로 실패하는 것이 아니라, 최소 계약이 없어서 단언이 실패하도록 테스트 골격을 바로잡는다.

### GREEN

- `Vec3`, `PlayerCommand`, `WorldState`, `GameSnapshot` 최소 타입
- 기존 `advanceFixedStep` 재사용
- `src/main.ts`를 피벗 bootstrap 선택 경계로 단순화
- perspective camera, 바닥 큐브와 플레이어 placeholder 렌더
- UI에 `PIVOT PROTOTYPE`과 입력 도움말 표시

### 검증

- 동일 600틱 snapshot hash 일치
- 기존 전체 테스트 통과
- 브라우저에서 perspective camera와 placeholder 월드 표시
- 새로고침 후 콘솔 오류 0

### 완료 게이트

렌더나 DOM 없이 피벗 session 테스트가 실행되고, 렌더는 snapshot만 읽는다.

## 마일스톤 1 — 3인칭 이동 세트

### 결과

WASD 이동, 카메라 조준, 점프·더블 점프·대시와 단순 테스트 앵커 와이어를 연결해 공중 코스를 통과한다.

### RED

- 카메라 기준 이동 방향 변환
- 세 번째 점프 거부와 착지 시 공중 점프 회복
- 대시 쿨다운·벽 충돌·착지 회복
- 와이어 사거리 밖·무효 표면 거부
- 와이어 당김 종료와 종료 후 속도 일부 보존

### GREEN

- XZ 이동·Y 중력의 세로 AABB 플레이어
- mouse yaw/pitch와 pointer lock input adapter
- jump/dash/wire edge command
- 테스트용 공중 발판과 wireable surface
- 카메라 shoulder follow와 카메라 충돌
- 표현 전용 와이어 선

### 브라우저 플레이테스트

1. 바닥에서 점프 후 공중에서 한 번 더 점프한다.
2. 대시로 첫 간격을 넘는다.
3. 공중 앵커에 와이어를 걸고 당김 도중 방향을 조절한다.
4. 와이어 해제 직후 대시·더블 점프로 마지막 발판에 착지한다.
5. pointer lock 해제·재진입 후 이동 입력이 남지 않는지 확인한다.

### 완료 게이트

캡처가 없어도 3분 동안 이동 자체를 반복해 볼 이유가 있고, 목표 발판 도달 성공률이 플레이테스터 3회 중 2회 이상이다.

## 마일스톤 2 — 셀 월드와 지형 절취 캡처

### 결과

조준한 표면을 중심으로 view-aligned 3m 큐브 안의 셀을 제거하고 LIFO 스택에 저장한다.

### RED

- OBB point containment와 world/local cell 변환
- 같은 월드·조준에서 같은 셀 목록과 순서
- 캡처 성공 시 원본 셀 제거와 stack push가 동시에 일어남
- 빈 캡처, 사거리 초과, 스택 가득 참, 216셀 초과 거부
- 실패한 캡처가 월드와 스택을 전혀 바꾸지 않음

### GREEN

- sparse cell map과 material/capturable/destructible 속성
- ray로 첫 캡처 가능 표면 선택
- camera basis 정육면체 캡처 볼륨
- `CapturedChunk`와 5개 LIFO 스택
- 재질별 instanced terrain과 dirty 갱신
- 캡처 예상 볼륨·셀 하이라이트와 HUD 스택 수

### 브라우저 플레이테스트

1. 정면, 위쪽, 비스듬한 각도에서 같은 바위를 캡처한다.
2. 각도에 따라 제거되는 셀 경계가 예상과 일치하는지 확인한다.
3. 캡처 후 실제 구멍을 통과하거나 바라볼 수 있는지 확인한다.
4. 스택이 가득 찼을 때 지형이 사라지지 않는지 확인한다.

### 완료 게이트

조준 미리보기와 실제 절취 결과가 일치하고, 계단형 경계가 슬라이스 방향 판독을 방해하지 않는다. 방해하면 다음 단계 전 렌더 재구성 게이트를 판정한다.

## 마일스톤 3 — 공중 배치와 와이어 결합

상태: 자동 검증 완료. 실제 pointer lock Q/E 조작 플레이테스트 대기.

### 결과

스택 최상단 청크를 공중에 배치하고 즉시 밟거나 와이어 목표로 사용할 수 있다.

### 구현 순서

#### 3A — 청크 anchor와 배치 변환

- `CapturedChunk`의 안정적인 anchor cell 선택
- capture local index를 목표 world cell로 변환
- 첫 검증 구현은 회전 없이 저장된 정수 `gridOffset`을 보존한다. 90도 yaw 회전은 플레이테스트 후 후속 범위로 둔다.
- 같은 입력에서 같은 목표 cell key 순서 보장

#### 3B — 전체 유효성 검사와 원자적 배치

- 사거리·월드 경계·terrain 겹침 검사
- 플레이어·보스·활성 투사체 보호 AABB 검사
- 배치 금지 볼륨 검사
- 전체 셀이 유효할 때만 stack pop과 terrain 등록
- 실패 코드를 값으로 반환하고 예외나 부분 배치를 사용하지 않음

#### 3C — 배치 ghost와 권위 결과 일치

- Q 누름 동안 매 렌더 프레임 ghost 표시
- Q 해제 시 가장 최근 조준 정보를 틱 command로 확정
- ghost가 사용한 순수 배치 계산 함수를 core transaction도 재사용
- 유효·무효 색과 실패 이유 HUD

#### 3D — 배치 셀의 collision·wire 등록

- 배치 성공 snapshot부터 플레이어 충돌에 포함
- 같은 셀 집합을 `wireRaycast` spatial index에 등록
- player-owned 셀의 collidable/capturable/destructible/wireable 기본값 적용
- 재캡처 시 원본 셀 제거로 셀 복제 방지

#### 3E — 와이어 당김 상태

- 가장 가까운 wireable 표면 hit와 플레이어-origin 차폐 재검사
- anchor point·cell key·잔여 tick을 가진 `WirePullState`
- 목표 속도 접근, 감소 중력과 제한된 횡조향
- 도착·입력 해제·시간 만료·충돌·anchor 파괴 종료
- 종료 속도 보존과 대시·더블 점프 연계

### RED

- capture local index가 목표 world cell로 결정론적으로 변환됨
- 청크 anchor 동률에서 항상 같은 셀이 선택됨
- 빈 스택 배치 거부
- 사거리 초과, 기존 셀 겹침, 플레이어/보스 내부 배치 거부
- 활성 투사체 보호 범위와 배치 금지 볼륨 거부
- 일부 셀만 유효한 배치의 전체 거부
- 성공 시 전체 셀 등록과 stack pop의 원자성
- 배치 직후 collision과 wire raycast에 같은 틱부터 포함
- 캡처→재배치 반복에서 terrain+stack 총 셀 수 불변
- 카메라에서는 보이지만 플레이어에서 차폐된 anchor 거부
- anchor cell 파괴 시 와이어가 다음 틱에 안전하게 종료
- 와이어 도착·조기 해제 후 속도 보존 상한

### GREEN

- 0.5m 그리드 목표점 양자화
- 공중 지지 검사 없는 placement transaction
- 배치 유효·무효 ghost preview
- 배치 지형의 렌더·충돌·와이어 표면 등록
- 캡처→배치→와이어 통합 session event
- Q hold/release 배치 입력과 E hold/release 와이어 입력
- `WirePullState`와 도착·파괴 종료 처리
- 스택·실패 코드·와이어 anchor HUD 피드백

### 통합 테스트 시나리오

```text
Given  공중 간격 앞의 capturable rock과 빈 stack
When   오른쪽 클릭 CaptureCommand를 확정
Then   rock 셀이 제거되고 같은 수의 CapturedChunk 셀이 stack에 생긴다

When   빈 공중 좌표에 PlaceCommand를 확정
Then   stack이 하나 줄고 player-owned 셀이 terrain에 등록된다
And    같은 snapshot의 collision과 wireRaycast가 새 셀을 찾는다

When   새 셀 표면에 WireCommand를 확정
Then   player.wire가 Pulling이 되고 플레이어가 anchor로 이동한다

When   도착 전에 배치 셀이 파괴됨
Then   다음 tick에 wire가 종료되고 플레이어 속도는 안전 상한 안에서 보존된다
```

### 브라우저 플레이테스트

1. 지형을 캡처한다.
2. 기존 점프로 닿지 않는 공중 위치에 배치한다.
3. 배치된 지형으로 와이어 이동한다.
4. 그 위에 착지하고 다시 캡처·배치해 두 번째 이동선을 만든다.
5. 잘못된 겹침 배치가 스택을 소비하지 않는지 확인한다.
6. Q를 누르는 동안 ghost를 움직이고 해제한 위치에 정확히 배치되는지 확인한다.
7. 배치 직후 별도 대기 없이 E로 와이어를 연결한다.
8. 와이어 이동 중 횡조향하고, 조기 해제 후 더블 점프와 대시를 연결한다.
9. 보스 대체 테스트 장치로 anchor를 제거해 줄이 안전하게 끊어지는지 확인한다.

### 완료 게이트

`캡처 → 공중 배치 → 와이어 이동`이 15초 안에 반복 가능하고, 다음 조건을 모두 만족해야 한다.

- 5회 연속 수행에서 스택·셀 수 불일치가 없다.
- ghost와 실제 지형의 눈에 띄는 위치 차이가 없다.
- 배치 후 1초 안에 같은 지형으로 와이어를 연결할 수 있다.
- 와이어 종료 후 대시·더블 점프를 연결해 목표 발판에 도달할 수 있다.
- 플레이테스터가 이 루프를 피벗의 핵심 재미 후보로 승인한다.

하나라도 실패하면 원인을 이동, 배치 UX, 캡처 형상 또는 와이어 튜닝으로 분류해 마일스톤 3 안에서 반복한다. 승인되지 않으면 보스 구현을 시작하지 않는다.

## 마일스톤 4 — 플레이어 사격과 보스 샌드백

### 결과

기본 hitscan 사격, 체력과 단순 보스 목표가 동작해 이동 중 조준·공격 감각을 검증한다.

### RED

- 발사 간격 제한
- 카메라 ray 목표를 무기 origin에서 재검사해 벽 뒤 명중 거부
- 보스 collider 명중과 체력 감소
- 체력 0에서 Dead 전이와 추가 피해 무시

### GREEN

- 왼쪽 클릭 hitscan
- 조준점, 명중 flash와 피해 HUD
- 고정된 보스 placeholder와 체력 bar
- 이동·와이어 중 사격 허용

### 브라우저 플레이테스트

- 지상, 대시, 더블 점프와 와이어 당김 중 사격한다.
- 카메라만 벽 밖에 있을 때 벽 너머 명중하지 않는지 확인한다.
- 이동하면서 보스를 추적할 때 카메라·조준이 과도하게 흔들리지 않는지 확인한다.

### 완료 게이트

사격이 이동을 멈추게 하지 않고 캡처·와이어와 입력 충돌이 없다.

## 마일스톤 5 — 보스 공격 캡처

### 결과

보스가 구체와 지형 청크를 예고 후 발사하고, 플레이어가 이를 캡처해 피해 없는 청크로 바꿔 배치한다.

### RED

- telegraph → fire → recover 상태 순서와 고정 tick
- 구체·지형 투사체 충돌 피해
- 캡처가 같은 틱의 투사체 피해보다 먼저 처리됨
- 지형 투사체 캡처 시 공격 엔티티 제거
- 캡처 청크에 velocity/damage가 남지 않음
- 캡처 불가 보스 본체와 일반 위험물 거부

### GREEN

- 고정 순환 boss FSM
- 구체와 셀 청크 투사체
- 공격별 색·형태·사운드 전 telegraph
- 캡처 가능한 공격의 조준점 표시
- 구체는 첫 데모에서 단일 셀 청크로 굳히는 임시 규칙

### 브라우저 플레이테스트

1. 공격 예고만 보고 구체와 지형 공격을 구분한다.
2. 회피했을 때 피해가 없고 피격했을 때 명확한 피드백을 확인한다.
3. 날아오는 지형을 캡처해 공격을 무효화한다.
4. 얻은 청크를 공중에 배치하고 와이어로 이동한다.

### 완료 게이트

공격을 단순 회피하는 것보다 캡처해 이동 자원으로 바꾸는 선택이 적어도 한 상황에서 명백히 유리하다.

## 마일스톤 6 — 지형 파괴와 보스전 완결

### 결과

보스가 기존·배치 지형을 파괴하고 플레이어가 새로운 이동선을 만들어 보스를 처치한다.

### RED

- 파괴 범위가 destructible 셀만 제거
- 캡처 불가 기반 지형과 보스 collider 보존
- 파괴된 배치 지형이 collision·wire raycast에서 함께 제거
- 추락·사망·리셋 상태 복원
- 보스 사망 후 승리 상태와 공격 중지

### GREEN

- TelegraphBreak와 범위 파괴
- 파괴 예상 영역 표시
- 플레이어 체력, 추락 복귀와 R 리셋
- 보스 사망·승리 UI
- 파괴 후 재구축할 캡처 재료 공급 규칙

### 브라우저 플레이테스트

- 보스가 이동 거점을 파괴하기 전에 예고를 읽는다.
- 파괴 후 남은 지형을 캡처·배치해 전투를 복구한다.
- 한 번 이상 공중 거점을 새로 만들며 보스를 처치한다.
- 사망과 리셋 후 terrain·stack·boss가 초기 상태로 완전히 돌아오는지 확인한다.

### 완료 게이트

보스전에서 캡처가 공격 무효화, 엄폐, 이동선 생성 중 두 가지 이상으로 실제 사용된다.

## 마일스톤 7 — 공중 섬 데모 맵과 최소 콘텐츠

### 결과

산·연못·나무·풀·바위·길이 있는 하나의 공중 섬에서 이동 학습부터 보스 처치까지 이어진다.

### 구현

- 셀 기반 섬 지형과 캡처 불가 기반 코어
- 산: 고도와 와이어 이동 학습
- 연못: 지형 구획과 시각적 랜드마크, 초기에는 수영 미구현
- 나무·바위: 캡처 재료와 엄폐
- 풀·길: 진행 방향과 안전 구역 표시
- 이동 튜토리얼 구간, 캡처·배치 구간, 보스 arena
- 일반 적 1종은 역할이 확정될 때만 추가하고, 미확정이면 데모 완료 조건에서 제외

### 검증 명령 대체 조건

맵 배치와 조작감은 자동 RED 대신 다음 브라우저 절차를 기록한다.

1. 설명 없이 길을 따라 1분 안에 캡처 재료에 도달한다.
2. 기존 길과 캡처 지름길을 모두 사용해 보스 arena에 진입한다.
3. 산·연못·나무·길을 플레이 카메라에서 구분한다.
4. 섬 외곽 추락 후 2초 안에 복귀한다.
5. 보스 포함 전체 세션을 5~10분 안에 완료한다.

### 완료 게이트

플레이테스터가 핵심 루프를 설명 없이 한 번 완주하고, 캡처를 최소 3회 이상 전투·이동에 자발적으로 사용한다.

## 마일스톤 8 — 안정화와 피벗 판정

### 자동 검증

- `pnpm test`
- `pnpm build`
- 결정론 10분 명령 시퀀스 snapshot hash
- 캡처·배치·파괴 반복 1,000회 상태 불변식
- terrain 20,000셀·투사체 64개 성능 시나리오
- `python tools/wiki_sync.py check`

### 브라우저 검증

- 1920×1080과 1280×720
- 새로고침·pointer lock 재진입
- 콘솔 오류 0
- 30분 연속 플레이에서 입력 stuck·셀 유실·스택 불일치 없음
- 캡처 예상, 실제 절취, 배치 ghost와 실제 충돌 일치

### 피벗 판정 질문

- 이동만으로 반복하고 싶은 손맛이 있는가?
- 지형을 잘라 공중에 놓는 행동을 처음 본 사람이 이해하는가?
- 캡처가 전투를 정지시키지 않고 공격·방어·이동 판단에 들어가는가?
- 보스의 지형 파괴가 불쾌한 리셋이 아니라 재구축 기회를 만드는가?
- 복셀 절취 품질이 핵심 아이디어를 충분히 전달하는가?

### 판정 결과

아직 미실행이다. 플레이테스트 후 피벗 제안의 각 항목을 `채택`, `보류`, `폐기`로 표시하고 본류 융화 절차를 시작한다.
