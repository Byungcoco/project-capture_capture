# ADR-0007: 게임 모드 FSM — core가 소유하고 render가 파생한다

> [[ADR-0010-pivot-to-third-person-capture-action|ADR-0010]]과 [[ADR-0011-cell-terrain-authority-architecture|ADR-0011]]로 대체됐다. 모드와 시간 정지가 사라져 GameMode FSM 자체가 없다. "진실의 원본을 하나로 둔다"와 "코스메틱은 파생으로 둔다"는 사상은 셀 지형 권위 구조에 그대로 이어졌다. 이 문서는 이력 보존용이다.

## 맥락

이 게임은 같은 입력이 상황마다 다른 일을 한다. 좌클릭이 어떤 순간엔 캡처고,
어떤 순간엔 붙여넣기다. 암묵적인 mode 변수로 버티다 보면 if 분기가 자라
스파게티가 되는 게 뻔히 보였고, 추후 스프라이트 캐릭터 교체(애니메이션 상태)와
리플레이 기록 범위까지 얽히면서 "상태를 누가 소유하는가"를 정해야 했다.
처음 떠올린 안은 GameMode와 Player에 각각 FSM을 두고 동기화하는 것이었다.

## 결정

FSM은 core에 하나만 둔다. GameMode FSM이 Platform / CaptureAim / Paste를
소유하고, 입력 매퍼가 원시 입력을 모드에 맞는 명령으로 번역하며, stepPlayer는
모드를 모른다. 애니메이션은 render 계층의 파생 FSM으로 두고 PlayerState에서
매 프레임 다시 계산한다.

캡처는 손에 드는 것이 아니라 슬롯(기본 3칸, 1/2/3 키)에 저장한다.
CaptureAim/Paste 동안 시뮬 틱은 정지하고, 조준은 시뮬 밖의 상호작용으로
두며, 확정 시에만 Capture/Paste 이벤트가 core에 들어온다. 리플레이는
플랫폼 입력 스트림과 이 이벤트만 기록하고 조준 과정은 기록하지 않는다.

CaptureAim 진입 시 첫 빈 슬롯을 자동 선택하고 세 슬롯이 모두 차 있으면
3번 슬롯을 기본 대상으로 삼는다. 조준 중 1/2/3으로 대상 슬롯을 바꿀 수
있으며, 캡처 확정 시 선택 슬롯을 즉시 덮어쓰고 Paste로 전환한다. 프로토타입은
빠른 반복을 위해 확인창을 두지 않으며 덮어쓰기 확인 UI는 후속 후보로 남긴다.

## 이유

- 동기화할 FSM이 두 개면 어긋나는 프레임이 반드시 생긴다. 진실의 원본을
  하나로 줄이면 동기화라는 문제 자체가 사라진다.
- 시간 정지 덕분에 조준은 월드에 부작용이 없다. 그렇다면 결정론에 필요한
  것은 확정된 캡처 파라미터뿐이고, 조준을 틱 단위로 기록하는 것은 데이터
  낭비다. 이벤트 기록이 리플레이를 가볍게 하고, 관전 시에도 우왕좌왕하는
  조준 대신 "찰칵" 순간만 보여줘 해법 피드 컨셉과 맞는다.
- 애니메이션은 코스메틱이다. 파생으로 두면 표현을 아무리 바꿔도
  시뮬레이션이 흔들리지 않는다.
- 슬롯 저장은 초기 기획의 "필름 제약"(캡처 자원 관리)을 조작 체계로
  실체화한 것이고, 키가 적은 조작(모드가 키의 의미를 바꾼다)은 퍼즐 게임을
  처음 잡는 심사위원이 3분 안에 이해해야 한다는 제약과 맞는다.

## 고려한 대안

- **GameMode + Player 이중 FSM 동기화**: 최초 안. 동기화 버그 표면이 커서 기각.
- **조준 과정까지 틱 단위 리플레이 기록**: 결정론적으로는 성립하나 데이터가
  무겁고 관전 가치가 낮다. 이벤트 기록으로 대체.
- **무거운 State 패턴(상태별 클래스, enter/exit 훅)**: 상태 세 개짜리 게임에
  과설계. enum + 전이 함수 + 명령 스위치로 충분하다.
- **캡처 중 실시간 유지**: 긴장감은 얻지만 차분히 각도를 찾는 재미와 충돌.
- **단일 스탬프를 손에 드는 방식**: 슬롯 도입으로 대체. 든 채 이탈 금지 같은
  예외 규칙이 필요 없어진다.

## 영향

- 입력 처리·카메라 권한·UI 표시가 전부 GameMode를 단일 기준으로 삼는다.
- 슬롯 HUD는 선택 슬롯과 점유 여부를 항상 구분해 보여줘야 한다.
- PlayerState에 facing 필드가 추가된다 (M2에서 반영).
- 모드 가시성(비네트, 프레임 오버레이, 슬롯 HUD)이 조작 체계의 필수 요건이
  된다 — M3 구현 시점부터 최소한의 표시가 있어야 한다.
- 열린 질문 두 개를 의도적으로 남긴다: 캡처 타이밍(계획형 vs 진행형)과
  붙여넣기 횟수 제한. 둘 다 M5 플레이테스트 후 결정하고 이 ADR을 갱신하거나
  후속 ADR로 잇는다.
