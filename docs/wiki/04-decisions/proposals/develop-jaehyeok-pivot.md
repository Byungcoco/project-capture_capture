# develop-jaehyeok 피벗 제안: 3인칭 캡처 와이어 액션

## 문서 지위와 적용 범위

이 문서는 `develop-jaehyeok` 브랜치에서만 적용하는 **피벗 변경 제안의 단일 원본**이다. 아직 `develop`·`main`의 확정 설계를 대체하지 않는다.

- 이 문서에 명시하지 않은 규칙은 기존 [[../../01-product/concept|Concept]], [[../../02-design/gameplay/game-rules|Game Rules]], [[../../03-tech/architecture|Architecture]], [[../../03-tech/capture-pipeline|Capture Pipeline]]을 참고한다.
- 기존 문서와 충돌하면 이 브랜치에서는 이 문서의 `확정 피벗 규칙`을 우선한다.
- 기존 accepted ADR은 이 브랜치에서도 이력을 보존하며 직접 폐기하거나 의미를 덮어쓰지 않는다.
- 피벗 검증 전에는 기존 원본 문서에 새 규칙을 분산 복제하지 않는다.
- 본류에 병합할 때는 이 문서를 그대로 영구 원본으로 삼지 않는다. 채택된 항목을 관련 제품·기획·기술 원본과 정식 ADR로 이동하고, 이 문서는 결과와 이동 링크를 남긴 뒤 `deprecated`로 전환한다.

## 피벗 한 줄 정의

공중 섬을 누비는 3인칭 슈터에서, 바라보는 방향으로 세계의 정육면체 지형 조각을 잘라 스택에 저장하고 공중에 다시 배치한 뒤 와이어로 당겨 이동하며 보스와 싸운다.

## 재미 가설

핵심 재미는 전투 공간을 **잘라서 탄약이자 이동 거점으로 재편집**하는 데 있다.

1. 보스가 파괴하거나 발사한 지형을 위험 속에서 포착한다.
2. 필요한 순간 지형을 캡처해 위협을 제거하고 스택에 확보한다.
3. 확보한 지형을 공중에 배치해 엄폐물·발판·와이어 앵커를 만든다.
4. 와이어·대시·더블 점프로 새 이동선을 즉석에서 구성한다.
5. 보스의 공격 때문에 계속 변하는 전장을 다시 캡처하고 재배치한다.

캡처는 별도 퍼즐 화면이 아니라 슈팅과 이동 중 즉시 사용하는 전투 동사여야 한다.

## 확정 피벗 규칙

### 시점과 기본 장르

- 기본 시점은 3인칭이다.
- 기본 장르는 3인칭 슈터와 고속 이동 액션의 결합이다.
- 조준 방향은 사격, 캡처 슬라이스 방향, 와이어 발사 방향의 공통 기준이다.
- 기존 2D 플레이 평면과 직교 퍼즐 플랫포머 규칙은 이 브랜치의 목표 플레이에는 적용하지 않는다.

### 지형 절취 캡처

- 캡처는 원본을 보존하는 실루엣 복사가 아니라 월드의 대상 부분을 **잘라내어 저장하는 절취**다.
- 조준한 지점을 중심으로, 바라보는 방향의 각도에 맞춘 슬라이스를 만든다.
- 슬라이스는 지나치게 깊은 관통 절단이 아니라 폭·높이·깊이가 비슷한 정육면체 캡처 볼륨을 기본으로 한다.
- 캡처 성공 시 잘라낸 지형은 캡처 스택에 항목으로 쌓인다.
- 캡처 항목은 원본 지형에서 분리된 배치 가능한 지형 조각이다.
- 정확한 한 변 길이, 사거리, 재사용시간, 스택 최대치와 원본 지형의 절단 메시 생성 방식은 플레이테스트 전 수치·기술 미확정으로 둔다.

### 배치

- 스택의 캡처 지형을 월드에 다시 붙여넣을 수 있다.
- 지면뿐 아니라 공중에도 고정할 수 있다.
- 배치된 지형은 발판, 엄폐물과 와이어 이동 목표로 사용한다.
- 공중 고정은 별도 지지 구조나 중력 검사를 요구하지 않는 것을 첫 데모 기본값으로 한다.
- 배치 가능 거리, 다른 지형과의 겹침 허용, 회전 자유도와 설치 미리보기 규칙은 미확정이다.

### 와이어 액션

- 와이어 액션은 기본 이동 능력이다.
- 플레이어는 유효한 지점 또는 배치한 캡처 지형에 와이어를 발사하고, 당김으로 그 지점을 향해 빠르게 이동한다.
- 와이어는 독립 시뮬레이션 오브젝트가 아니다. 판정은 플레이어와 목표 지점 사이의 이동 능력으로 처리하고 줄·궤적은 표현 계층에서 파생한다.
- 첫 데모에서는 복잡한 로프 물리, 줄 감기, 줄 절단과 지속 스윙 시뮬레이션을 범위에서 제외한다.

### 추가 이동 능력

- 대시를 제공한다.
- 더블 점프를 제공한다.
- 와이어·대시·더블 점프는 공중에서 배치한 지형 사이를 끊김 없이 연결하는 하나의 이동 세트로 튜닝한다.
- 세 능력의 횟수 회복, 쿨다운, 관성 보존과 입력 조합은 플레이테스트 대상이다.

## 캡처 대상과 전투 상호작용

| 대상 | 캡처 결과 | 캡처 전 위험 | 캡처 후 상태 |
|---|---|---|---|
| 일반 지형 | 정육면체 지형 조각이 스택에 추가됨 | 없음 또는 환경별 규칙 | 배치 가능한 일반 지형 |
| 보스의 구체 투사체 | 캡처 가능한 스택 항목 후보 | 접촉 또는 피격 피해 | 피해 없는 캡처 항목으로 정규화할지 미확정 |
| 보스가 생성한 지형 | 지형 조각이 스택에 추가됨 | 생성 방식에 따라 없음 | 배치 가능한 일반 지형 |
| 보스가 발사한 지형 | 지형 조각이 스택에 추가됨 | 비행 중 피격 피해 | 캡처 순간 공격성과 피해를 잃은 일반 캡처 지형 |

보스가 발사한 지형은 캡처 후 더 이상 공격 판정을 갖지 않는다. 캡처 항목은 원본 공격 엔티티를 그대로 보존하지 않고 안전한 배치 지형 계약으로 변환한다.

구체 투사체의 붙여넣기 결과와 용도는 아직 확정하지 않는다. 지형과 동일하게 굳히는 안, 플레이어 투사체로 되쏘는 안, 캡처 즉시 자원으로 바꾸는 안을 데모 전 결정해야 한다.

## 데모 맵

### 공간

- 하나의 공중 섬을 사용한다.
- 섬에는 산, 연못, 나무, 풀, 바위와 길이 있다.
- 환경 요소는 장식에 그치지 않고 이동 경로, 엄폐, 캡처 재료와 보스 파괴 대상으로 역할을 나눈다.
- 섬 외곽 추락은 빠른 재시작 또는 체크포인트 복귀로 처리한다.
- 플레이어가 기존 지형만으로도 기본 탐색은 가능하되, 전투 중 유리한 고도와 접근선을 만들려면 캡처 배치가 필요하도록 설계한다.

### 보스

- 구체 투사체를 발사한다. 구체는 플레이어에게 피해를 주며 캡처할 수 있다.
- 지형을 생성하거나 지형 조각을 발사한다.
- 날아오는 지형은 피해를 주지만, 캡처되면 피해 없는 일반 캡처 지형이 된다.
- 기존 지형과 플레이어가 배치한 지형을 파괴할 수 있다.
- 보스전은 `위협 캡처 → 공중 배치 → 와이어 접근 또는 회피 → 사격`의 반복을 검증해야 한다.
- 보스 체력 단계, 약점, 공격 예고, 캡처 가능 시간과 승리 조건의 상세는 미확정이다.

### 일반 적

- 일반 적이 존재한다.
- 공격 방식과 역할 구성은 아직 미확정이다.
- 일반 적은 보스전의 축소판을 반복하기보다, 이동·조준·캡처 중 하나를 학습시키는 역할로 설계한다.

## 첫 플레이 가능 데모의 최소 루프

```text
공중 섬 탐색
→ 일반 지형 한 조각 절취 캡처
→ 스택 확인
→ 공중에 지형 배치
→ 와이어로 배치 지형까지 이동
→ 대시·더블 점프로 다음 구간 연결
→ 보스 조우
→ 보스의 지형 공격을 캡처해 무력화
→ 캡처 지형으로 이동선·엄폐 생성
→ 보스 처치
```

데모는 이 루프가 처음부터 끝까지 한 번 이어질 때 성립한다. 일반 적의 완성도, 다중 맵, 성장, 장비와 장기 콘텐츠는 이 루프 이후다.

## 본류 융화 절차

피벗을 `develop` 또는 `main`에 반영하기 전에 다음 순서를 따른다.

1. 플레이테스트 결과로 각 피벗 항목을 `채택`, `보류`, `폐기`로 판정한다.
2. 장르·핵심 동사·아키텍처처럼 기존 결정을 뒤집는 항목은 정식 ADR을 추가하고 supersede 관계를 명시한다.
3. 채택된 현재 사실을 Concept, Game Rules, Architecture, Capture Pipeline과 새 분야별 원본에 직접 반영한다.
4. 코드 계약과 실제 구현이 생긴 항목만 `06-code` 원본으로 이동한다.
5. 이 문서의 표를 최종 이동 링크와 판정 결과로 갱신하고 상태를 `deprecated`로 바꾼다.
6. 생성 인덱스와 로그는 `wiki_sync.py finalize`로 동기화한다.

브랜치 전체를 한 번에 병합하기보다, `규칙 원본과 ADR → 순수 도메인 계약 → 이동 프로토타입 → 캡처·배치 → 전투·데모 맵` 순서로 검토 가능한 변경 단위를 만든다.

## 미확정 질문

### 캡처와 스택

- 스택 최대 개수와 같은 종류의 중첩 수는 얼마인가?
- 캡처한 항목은 배치 시 소모되는가?
- 절취한 원본 지형의 구멍은 영구 유지되는가, 보스전 종료나 시간 경과로 복구되는가?
- 캡처 볼륨이 여러 재질·오브젝트·적을 동시에 포함하면 어떻게 분리하는가?
- 움직이는 투사체를 캡처할 때 시간 정지나 조준 보정이 필요한가?

### 배치와 이동

- 공중 배치의 사거리와 설치 금지 구역은 어떻게 정하는가?
- 배치 지형은 자유 회전인가, 캡처 당시 방향을 유지하는가?
- 와이어는 직선 당김만 제공하는가, 목표 도착 전 해제와 관성 보존을 허용하는가?
- 대시와 더블 점프는 지형 착지, 와이어 연결 또는 시간으로 충전되는가?

### 전투와 콘텐츠

- 플레이어의 기본 무기, 사격 자원과 피해 모델은 무엇인가?
- 캡처한 구체 투사체는 어떤 방식으로 재사용하는가?
- 보스가 플레이어 배치 지형을 파괴할 때 사전 경고와 대응 시간은 얼마인가?
- 일반 적은 지상 추격, 원거리 견제, 공중 이동 중 어떤 역할부터 구현하는가?
- 연못·나무·바위 등 자연물이 절취·배치될 때 시각과 충돌을 어떻게 단순화하는가?

## 피벗 검증 기준

- 지형을 조준하고 절취해 스택에 넣는 행동을 별도 설명 없이 이해할 수 있다.
- 공중에 배치한 지형이 즉시 와이어 이동 목표로 읽힌다.
- 와이어·대시·더블 점프를 연결했을 때 이동이 끊기지 않고 의도한 지점에 도달한다.
- 보스의 지형 공격을 피하기만 하는 것보다 캡처해 재사용하는 선택이 유리하고 즐겁다.
- 보스가 지형을 파괴해도 플레이어가 새 지형을 만들어 전투를 복구할 수 있다.
- 캡처가 슈팅을 중단시키는 별도 퍼즐 모드가 아니라 전투의 공격·방어·이동 판단으로 작동한다.
